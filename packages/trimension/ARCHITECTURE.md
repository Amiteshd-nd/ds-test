# trimension — what actually exists

Written at the end of M0–M7, describing the code as built rather than as planned. Where
it diverges from [`PRD.md`](./PRD.md), the divergence and its reasoning are marked
**deviation**.

- **Status:** M0–M7 implemented. 136 Rust tests, `clippy -D warnings` clean, all three
  compile targets building.
- **Not built:** DWG import, real-time multi-human presence, text rendering, wgpu inside
  the browser shell (the renderer compiles for wasm32 but the shell draws through a 2D
  canvas — see *Renderer* below).

---

## 1. Invariant audit

The question PRD Prompt 6 asks: for each invariant, is it enforced **structurally** (the
compiler forbids the violation), **by test** (CI catches it), or **conventionally** (only
discipline)? Anything conventional is a finding.

| # | Invariant | Enforcement | Evidence |
|---|---|---|---|
| **I1** | Single write path | **Structural** | `Document::apply` takes a `Validated`, whose fields are private and whose only constructor is `validate::check`. Two `compile_fail` doctests in `crates/doc/src/validate.rs` prove a proof cannot be forged. A `revision` field on the proof also makes validate-then-mutate races impossible. |
| **I2** | Rust owns the document | **Structural** | The wasm boundary exposes no `getDocument`, no entity list, and no op type. JS receives query results, summaries, measurements and layer metadata only. The shell's viewports hand a canvas to Wasm and geometry goes straight to the GPU, so no vertex coordinate crosses into JavaScript at all. (The earlier 2D fallback did leak coordinates through a `render_outlines` query; that path and the query are removed.) |
| **I3** | Tools and UI are the same commands | **Structural + test** | One `Command` enum in `crates/api/src/command.rs`. Schemas are generated by `cargo xtask gen-schemas`; three tests assert registry↔schema agreement in both directions, and one asserts no raw `Op` variant leaks into any tool schema. CI additionally runs `git diff --exit-code` on the generated files. |
| **I4** | Provenance on every derived value | **Structural + test** | `Tracked<T>` wraps the *value*, so a number cannot be stored without a record. `validate::check` rejects an empty reason. `Tracked::combine` takes the worse of two provenances, which prevents confidence laundering. Tests assert the messy fixture yields zero `Measured` values. |
| **I5** | No whole-model context | **Structural + test** | No serialisation entry point exists on the tool surface. `query_entities` has a hard cap the caller cannot raise (tested), returns a truncation flag, and `describe_region` returns aggregates whose serialised form is asserted not to contain entity lists. |
| **I6** | Render parity | **Test, and stronger than the PRD asked for** | `render::view` runs with no window, canvas or display server. The parity test asserts **byte equality of the scene buffers** both surfaces consume, not pixel similarity — see §4. |
| **I7** | Plan before apply | **Structural** | `ApprovedPlan` has a private constructor reachable only via `Plan::approve`. `Author::Agent(AgentId, PlanId)` has no variant without a plan, so an unattributed agent commit is unrepresentable. Verified end to end in the browser: 6→7 entities only after approval. |
| **I8** | Imports are additive | **Test** | Phase A loads DXF losslessly into `SourceSchema`; a test asserts a re-import doubles the source count rather than overwriting. Nothing in the codebase mutates a `SourceEntity` after insertion — but that is *conventional*, not structural. **Finding.** |

### Findings

1. **I8 is not structurally enforced.** `SourceSchema` exposes `insert` as `pub(crate)`
   and no update method, so the current code cannot rewrite source data — but nothing
   stops a future `Op::UpdateSourceEntity` being added. The fix is cheap: make the source
   schema append-only in the op alphabet by construction, and add a test that hashes the
   source subtree before and after a derived-object edit.
2. **A metric that was vacuously true, found by running it.** `render_view` returns
   `ink_fraction` so a caller can tell whether the camera framed anything. It compared
   readback bytes against the *linear* clear colour while the target is
   `Rgba8UnormSrgb`, so every pixel counted as ink and the answer was always 1.0 — and
   the tests asserting `> 0.001` passed for the same wrong reason. Fixed by deriving the
   background from the scene through the sRGB transfer function, and the tests are now
   bounded on both sides. Worth recording as a class: a one-sided assertion on a metric
   nobody has eyeballed is not a test.
3. **CI was not running what it claimed to.** The first push failed on
   `wasm-bindgen-test-runner` being absent — the workflow never installed it, and it only
   worked locally because it had been installed by hand. Fixing that exposed two worse
   problems in the steps that had never run: lavapipe was installed *after* the tests, so
   `cargo test` had no adapter and every renderer test took its skip path; and
   `WGPU_BACKEND` was being ignored outright, because `InstanceDescriptor::
   new_without_display_handle()` does not read the environment. A green build would have
   meant "the renderer was never exercised". There is now a `gpu_check` example that fails
   with the adapter list before any test runs, and `TRIMENSION_REQUIRE_GPU` turns a skip
   into a failure. General lesson: a test that can skip itself needs a CI mode where
   skipping is an error.
4. **`tri-geom2d` has no tests of its own.** Its healing, pairing and profile logic is
   covered — 26 tests — but they live in `tri-solid`'s suite because that is where the
   pipeline is assembled. Coverage is real; the placement is wrong, and a change to
   `geom2d` alone shows a green `cargo test -p tri-geom2d`. Move them.

## 2. Decisions a professional drafter would dispute

Every one of these is visible in provenance. That is the bar the PRD sets, and it is met —
but "visible" is not "right", and these are the places a reviewer's attention is owed.

| Decision | Where | Disputable because | Visible? |
|---|---|---|---|
| Wall height defaults to 2700mm | `RuleSet.default_wall_height_mm` | It is a guess about the building, not a reading of the drawing. Every wall in every fixture inherits it. | Yes — `Assumed`, reason names the field it came from. Tested. |
| A 900mm line on an unrecognised layer becomes a wall | `wall.geometry.long_line` | In the messy fixture this misclassifies a **door leaf** as a wall. A drafter would object immediately. | Yes — `Assumed`, reason says "last resort". Pinned by a test that documents it as a known limitation. |
| Openings are hosted to the nearest wall within 2m | `classify::nearest_wall` | Proximity is not hosting. A door in a thin partition next to a thick one can attach to the wrong side. | Partially — the opening records its rule, but *which wall was chosen and why* is not in the reason string. **Weakest link in the provenance story.** |
| Opening dimensions default by kind (door 900×2100, window 1200×1500) | `classify::opening_op` | Block references carry no dimensions in our fixtures, so every opening is a typical size rather than a real one. | Yes — `Assumed`, each with a reason. |
| Corners are not mitred | `profile::build` | Offsetting each segment independently leaves a notch inside and an overshoot outside every corner, bounded by wall thickness. On a plan this is visible at any real zoom. | **No.** The limitation is documented in the module and here, but it produces no provenance record on the affected profile. **Finding.** |
| Arcs are tessellated at import | `dxf_importer::tessellate_arc` | A 2mm chord tolerance is a decision about how much curve fidelity matters. Exact parameters survive in the source schema, but derived geometry is polygonal forever. | Partially — the tolerance is not recorded on the derived entity. |
| Units guessed from extents when `$INSUNITS` is absent | `units::resolve` | An 8-unit drawing is "only plausible as metres" — a reasonable inference that is nonetheless a guess about the whole model's scale. | Yes, and loudly: `Assumed`, and the reason ends "verify before building". Tested. |
| Healing snaps endpoints within 5mm | `heal::heal` | 5mm is a judgement about drafting sloppiness. Too large merges genuinely separate elements. | Yes — every snap is reported with its distance, and gaps *not* closed are reported too. |

The two entries marked as findings — opening host selection and unmitred corners — are the
concrete work items before this model could be signed off by a real reviewer.

## 3. What I would do differently starting M0 again

1. **Merge `doc` and `commit`, or split them differently.** The PRD's dependency graph puts
   `validate` in `commit`, but `pub(crate)` does not cross a crate boundary, so that layout
   forces `doc` to expose public mutators. The fix used here — bind the proof to the
   *operation* rather than the *caller* — is better than what the PRD asked for and made
   the crate split harmless. I would design it that way from the start rather than
   discovering it while writing Prompt 2.
2. **Fixed-point coordinates from line one.** Adopting `i64` micrometres was a deviation
   made at M1; it is the single reason the cross-target determinism test passes at M4 and
   not just at M1. Retrofitting it later would have been a rewrite of every component.
3. **Put `Plan` in `api`, not `commit`.** `PlanStep.ops: Vec<Op>` was the PRD's shape and
   it is wrong — it hands the agent a lower-level write path than the UI has. This was
   flagged before any code was written, and it *still* shipped into M1 and only surfaced as
   a runtime error during M7 browser testing. Type-level objections should be acted on
   when raised, not noted and deferred.
4. **Spike the risky dependency at M0, not M4.** `manifold-csg` was flagged as unverified
   in `VERSIONS.md` on day one. The spike happened at M4 and found it needs CMake natively
   and an *unstable* feature plus LLVM 20 for wasm. That is a two-minute check that would
   have changed the M4 plan before any of it was written.
5. **Write the parity test's real assertion first.** The PRD asks for pixel comparison and
   notes it should be "hard to delete accidentally" — a smell. Deciding early that the
   guarantee is *scene-buffer equality* would have saved building toward the weaker test.
6. **Fixtures should exercise the inferences, not just the format.** Three fixtures all
   drew walls as single lines, so wall pairing — the highest-consequence inference in the
   pipeline — had zero end-to-end coverage until a fourth fixture was added at M4. Fixtures
   should be designed against the *decisions* under test.

## 4. What exists

### Crates

```
crates/
├── doc/          document, ids, components, layers, ops, validation, hashing
├── commit/       Commit, Author, Plan, Sequencer, LocalSession (optimistic apply)
├── geom2d/       heal, pair_walls, profile, R-tree index
├── solid/        extrude, opening subtraction, tessellate, the 2D→3D pipeline
├── import-dxf/   Importer trait, DXF phase A/B, rule engine, unit resolution
├── render/       wgpu: scene extraction, browser surface, headless surface
├── api/          command registry, query layer, tool registry, schema generation
├── wasm/         wasm-bindgen boundary (marshalling only)
└── server/       axum session server, websockets, blob store
apps/
├── web/          React + XState shell: canvas, inspector, chat, plan approval
└── agent/        AI SDK 7 host, tool bridge, approval loop
```

Dependency rules from PRD Prompt 1 hold exactly, with one mechanism worth noting: `server`
and `wasm` depend on `api` *only*, and reach document types through `pub use` re-exports
from `api`. The rule stays true in every `Cargo.toml` rather than being aspirational.

### Document model

`Document` holds `BTreeMap<EntityId, ComponentSet>`, a `LayerTree`, a `TypeRegistry`, a
`SourceSchema` and an `IdAllocator`.

**Deviation from PRD §4.3:** `BTreeMap` + a monotonic counter instead of `SlotMap`. Slotmap
keys carry a generation, so ids would not be a pure function of commit history, and its
iteration order is an implementation detail the document hash would depend on. Nothing was
lost: PRD §4.3 says ids are stable for the document's life, so slot reuse was never wanted.

**Deviation from PRD §4.3:** coordinates are `i64` micrometres, not floats. Reasoning in
`crates/doc/src/units.rs` and item 2 above.

**Deviation from PRD §4.3:** `Provenance` is a value wrapper (`Tracked<T>`) in field
position, not only an entity-level component. One record per entity cannot express a wall
whose height is `Assumed`, thickness `Inferred` and outline `Measured` — it collapses to
"mixed", which is the non-answer a reviewer cannot act on. The entity-level component is
retained for the separate question of how the entity came to exist.

### Commit model

Content-addressed `CommitId` over (parent, author, ops, message), so a retry deduplicates.
`Sequencer` is the authority; `LocalSession` is the client's optimistic layer.

Rejection handling is **rebuild-and-replay**, not inverse ops: keep the last acknowledged
document, replay the pending queue onto it, drop what no longer validates and report what
was dropped. Inverse ops would be a second implementation of every mutation and would drift.
PRD §4.4 gives this one sentence; it is implemented and tested at M1 because the document
model has to be built knowing apply is not one-directional.

### Import

Phase A is lossless (I8). Phase B is a **data-driven rule engine** — `crates/import-dxf/
rules/ncs-default.json` — with signal priority as numeric weights: layer 400, block 300,
linetype/lineweight 200, geometry 100. A test greps the classifier source to assert it
contains no layer-name string.

Units: `$INSUNITS` when present and plausible → `Measured`; present but implausible →
`Inferred` with a warning; absent → `Assumed` from an extents heuristic, with a reason that
ends "verify before building".

### 2D→3D

heal → pair → profile → extrude → subtract → tessellate, all emitted as commits.

**Deviation from PRD §4.5: no Manifold.** The spike found `manifold-csg-sys` needs CMake
natively and the crate's own `unstable-wasm-uu` feature (LLVM 20+, no exceptions, reduced
API) for `wasm32-unknown-unknown`. Beyond the build problems, a general float mesh boolean
in C++ is not bit-identical across targets, which would break the document hash M1 is built
on — the failure mode being client and server disagreeing about a document.

Instead the narrow problem is solved exactly: subtracting axis-aligned rectangular openings
from a prismatic wall is a 2D problem swept through the thickness. The wall is built from
the material that *remains* — panels, lintels, sills — so it is closed by construction with
no boolean to go wrong. Volumes are exact to 1e-3 m³ in tests and meshes pass an
edge-pairing closure check. This covers every opening a DXF block reference can describe.
Non-rectangular openings, true solid union at arbitrary wall junctions, or real fillets
would need a kernel; that is the moment to revisit, and it has not arrived.

### Renderer

`wgpu 30`, one WGSL shader, three pipelines (mesh, depth-tested lines, overlay lines), two
surfaces. Scene extraction is pure, integer-driven and target-independent.

**Four views**, all from the same scene data and the same shader:

| View | Projection | Notes |
| --- | --- | --- |
| Plan | orthographic, down −Z | Lines draw over fills; everything is coplanar. |
| Left elevation | orthographic, from −X | Depth-cued so openings read as recesses. |
| Right elevation | orthographic, from +X | |
| Two-point perspective | perspective, level eye at 1600mm | Verticals stay vertical — see below. |

Two-point is not a free orbit and the difference is the point. The view direction is
horizontal and the picture plane vertical, so vertical edges project parallel and the
scene has exactly two vanishing points. Tilting adds a third and every vertical converges,
which is what makes a casual 3D orbit look wrong to anyone who draws buildings. There is
no pitch parameter to pass in, and a test asserts verticality across five plan positions.

Three renderer bugs found by looking at output rather than by tests, all now covered:

- The orthographic depth mapping put everything beyond the mid-plane at negative clip z,
  so **half of every elevation was being clipped away**. It looked plausible because the
  surviving half was the half facing the camera.
- The two elevations were **swapped**: the screen basis was derived with a cross product
  and the handedness came out backwards. Invisible on a symmetrical building.
- Feature edges are extracted by crease detection rather than by drawing every triangle
  edge, which was putting a diagonal across every rectangular face.

The browser draws through the same `tri_render` code as the agent's headless PNG, on a
canvas swapchain. One caveat, recorded rather than hidden: the pipeline pins one sRGB
format, and a WebGPU canvas that prefers BGRA therefore pays an extra copy per present
(Chrome warns about it). Taking the surface's preferred format was tried and produced a
black canvas; it is a real optimisation and it is not worth a broken viewport.

**Deviation from PRD Prompt 4 on the parity test.** The PRD asks for a pixel comparison
within tolerance. That test compares a developer's Metal driver against CI's software
rasteriser, so its threshold is a driver-difference budget rather than a correctness one —
and the PRD's own note that it must be "hard to delete accidentally" is the tell. The
guarantee implemented instead is **byte equality of the scene buffers both surfaces
consume**, which is deterministic, GPU-free, fast, and cannot be made to pass by loosening
a number. A golden-fingerprint test and a headless smoke render sit on top.

Measured: **5,000 entities at 1920×1080 in 3.16 ms/frame including full CPU readback** — the
60 FPS bar is 16.6 ms, and an interactive canvas does not pay the readback.

Text is not rendered. The reason, and why MSDF is the wrong answer for non-Latin scripts, is
in `crates/render/src/lib.rs`.

### Session server

axum on **port 8788** (the repo forbids ports starting with 4 or 5). One in-memory session
per document; documents are files in blob storage, one per model, written via temp-file
rename. A `Store` trait leaves room for S3.

Verified: two browser clients and one headless agent client converge on an identical
document hash; a stale parent is rebased rather than refused; a rejection reaches only its
author.

One bug worth recording because it would have shipped: the wire protocol was originally
internally tagged, and serde's `Content` buffering cannot round-trip a map with
newtype-integer keys — which `Document` is. It worked for every empty document and failed
for every non-empty one. The protocol is adjacently tagged now.

### Tool surface

Five tools, schemas generated. **Deviation from PRD §4.7:** the write tool is
`apply_commands`, not `apply_commit(ops)`. §4.7 contradicts I3 — a raw op list is a
lower-level write path than the UI has, giving the agent *more* privilege than a human,
which is the Motif trap from §2 inverted. Invariants outrank architecture notes (PRD §3 is
explicit), so `Op` is not reachable from the tool surface at all, and a test asserts it.

### Shell

React 19 + XState 5 on **port 6178**. The approval gate is an explicit FSM, and approval is
per-plan and never standing. Provenance is surfaced two ways: dashed amber on the drawing
for entities whose *geometry* rests on an assumption, and the full field-by-field record in
the inspector. Grading matters — flagging every entity with any assumption marks the whole
drawing (nearly every wall has a defaulted base elevation), and a uniformly amber plan tells
a reviewer nothing.

## 5. Running it

```bash
cargo xtask test-all      # all three targets + native and wasm32 tests
cargo xtask parity        # the I6 guard
cargo xtask gen-schemas   # regenerate tool schemas (CI checks these are current)
```

The Rust toolchain lives in `.toolchain/` inside this package, so it satisfies the repo's
scope guardrail and is removable with `rm -rf .toolchain`. Set `RUSTUP_HOME`, `CARGO_HOME`
and `PATH` to it, or install 1.98.1 normally.

```bash
corepack pnpm --filter @trimension/web dev     # shell on :6178
cargo run -p tri-server                        # session server on :8788
```
