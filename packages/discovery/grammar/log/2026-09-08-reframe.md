# 2026-09-08 · Program-level reframe

**What happened.** Checked the project slate against Sarvam's actual Indus platform. Two of five
surfaces were framed wrongly, one was half right. Recording it here rather than quietly fixing it,
because these are the most useful entries the log will ever hold.

---

## Deprecated: `voice` as an end-user app

**What I believed.** Voice Agents meant designing the experience of a person *talking* to an agent —
a hands-free duty-status co-pilot for a truck driver: highway-signage aesthetics, 80px type,
sunlight contrast, a cracked-screen safe area, an on-device degraded mode.

**What's actually true.** Voice Agents is an authoring and ops console. You describe the agent, it
gets built, you simulate a thousand calls before the first real one, then rent a number and go live.
The user is the person *making* the agent, not the person talking to it.

**Why the mistake was interesting.** It was a plausible reading of "Voice Agents" and it produced a
whole visual theme (`[data-product="voice"]`, v1) that had to be thrown away — signage colours,
enormous type, ambient-brightness variants. All of it correct for a problem nobody asked me to
solve.

**What replaced it.** A test-bench theme: spec on one side, evidence on the other, distribution
before score, regression loud. The old theme is gone from `tokens.css` but the reasoning is here.

**What it cost.** The whole visual direction, plus the Spoken Echo and Degraded Mode patterns lost
their primary home. Both survive, demoted to secondary uses — which is itself a finding: a pattern
that only had one home was never proven.

## Deprecated: `coding` as an API playground

**What I believed.** Coding Agents meant the developer console — a comparison playground with a
latency waterfall, model selection, time-to-first-call onboarding.

**What's actually true.** Coding Agents is long-running runs where the plan stays visible so you can
change direction mid-run, with checkpoints as it goes. That's Taskgraph + Commit Boundary +
steering.

**What replaced it.** The run-supervision brief. The playground wasn't wrong as a *surface* — it's
the inference stack and docs layer, so it moved to `shell` where it belongs.

**What it cost.** Nothing, in the end. Latency Waterfall survived as a component inside the run
view. The lesson was about which project a surface belongs to, not about the surface.

## Reframed: `work` and `content`

Right patterns, wrong domains.

- `work` was NBFC document ops; it's actually knowledge work — email triage, briefings, helpdesk,
  lead follow-up, wired into Gmail/Slack/Notion. Delegation Envelope, Exception Queue and the audit
  trail all transferred unchanged, which is decent evidence the patterns are real rather than
  scenario-specific.
- `content` was marketing copy; it's actually Content Studio — voices, cloning, dubbing, live
  translation. The medium changed from text to audio/video, which made the problem *harder* (you
  can't scan audio; pronunciation failures are invisible in a transcript; dubs have to fit the
  shot). Back-translation Mirror survived and got stronger.

---

## Structural thing I missed entirely

Indus is **one shell** — one sign-up, one payment gateway, one credit system. That reframes the
design system from a nice-to-have into the actual job, and added a sixth project (`shell`) plus
pattern 17. Also Kivi is a voice layer cutting across all surfaces, which means voice is not one of
the five surfaces so much as a mode available in all of them.

**Takeaway for the case study.** Four patterns were missing from the grammar entirely — Behaviour
Spec, Simulation Sweep, Fleet Handoff, Cross-surface Shell — because I'd only thought about
*supervising* agents, not *making* them. The supervision half of this space is crowded. The
authoring half is nearly empty.
