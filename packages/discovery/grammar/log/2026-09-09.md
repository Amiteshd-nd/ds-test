**Pattern changes**
- *Latency Waterfall* v1 → v1.1. v1 had a single sample. What broke: the pattern's own rule says
  distribution not one sample, and there was no event that could carry one. v1.1 adds
  `latency.distribution` with p50/p95 and a required `source: 'measured' | 'placeholder'`. Cost: one
  more event, and the UI now has to say out loud when its numbers are invented — which it should.
- *Back-translation Mirror* v1 → v1.1. v1 had `backtranslation` with sentence-level drift. What
  broke: a dropped regulated clause is not a rephrasing, and `removed` on a sentence diff buries the
  legal failure in a typographic one. v1.1 adds `clause.dropped` with a `regulated` flag, ranked
  above everything else. Cost: one more event and a second place to look for meaning loss.
- *Confidence Without Numbers* v1.1 → v1.2. The two-axis rule held, but nothing said what to do
  when the two axes disagree and the surface has to *rank* nine of them. v1.2 says the ranking is
  derived, never named — and the derivation is a named function in the reducer so it can be argued
  with rather than tuned in a component.
- *Commit Boundary* v1 → v1.1. v1's `checkpoint` had no state, so `CHECKPOINT_PARTIAL` from the
  brief was unrepresentable. v1.1 adds `checkpoint.state`. Cost: nothing yet.

## Later — the webinar notes, and the correction they forced

`docs/sarvam-voice-agents-webinar.md` is the first source in this program that describes how the
real product is actually shaped rather than what a designer imagines it to be, so it got read
against the built surface rather than filed. Full accounting in `docs/webinar-gap-analysis.md`:
ten gaps, seven closed, three deliberately left.

**The one that mattered.** The surface treated an agent as *a list of rules* — hard constraints and
soft guidance, and a sweep whose outcomes were seven categories this interface invented. An agent is
a **prompt document with named sections**, plus **tools with latency budgets**, plus **input and
output variables**, plus a **goal defined against an output variable**. Everything downstream was
built on a model of the object that was wrong in the most expensive way: the evidence floated free
of the thing being evaluated. A sweep is now measured against a goal *she* defined, and a test
enforces that the goal names a variable that actually exists.

**Expected behaviours are the evaluation primitive**, not clusters. Clusters answer "what went
wrong"; a behaviour answers "which of the things I said should happen didn't", which is the question
an author has. A broken behaviour links down to the calls that broke it — so the four altitudes now
have a fifth entrance, and it is the one a person reaches for first.

**A tool budget is a latency budget.** Over 5s the caller hears dead air; 30s is the hard stop. This
is the clearest case in the program of a number that is really an interaction: drawn as a warning,
not a field.

**Turn-taking is where latency is felt, and it is configurable** — eagerness, interruption
threshold, nudges before hangup. Three new faults: an interruption misfire on a noisy line, a tool
over budget, and a call parked on hold music.

**`LIVE_DIVERGING` was a word with nothing behind it.** It now carries production numbers beside
simulated ones, per measure, worse side marked. Not a Monitor dashboard — the brief says one drift
signal is enough, and a dashboard is a sixth project.

**Fixed while doing it**
- The coverage guard failed with 15 newly declared states and no case naming them. Closed by naming
  them on the cases that genuinely demonstrate them, not by widening the whitelist — the mistake
  already caught once here, where a whitelist covering for a missing state defeats the test.
- `projects/voice/states.md` still said "proposed, not confirmed" and "Forty-one states" two turns
  after both decisions were made. Stale planning docs are how a wrong model survives.

**Deliberately not built**
A full Monitor surface (it is a dashboard, and this program is about judgement under uncertainty),
an authoring copilot (it designs the agent, which is the thing being studied), and
campaigns/pricing/integrations (commerce, not judgement). Written down in the gap analysis so the
omissions are choices rather than oversights.
